# Key bindings

Navigation, edit, accept and cancel keys are all configurable. A field never asks for a fixed key - it asks for a semantic **action** (`MoveUp`, `Accept`, `Toggle` - the full set is listed below), and a **key map** binds each action to one or more keys. Key bindings describe the terminal, not the questionnaire, so you set them on the `Tui` facade with `->keys(...)`, mirroring `->theme(...)`:

```php
$tui = (new Tui($form))->keys('vim');   // built-in vim navigation (h/j/k/l)
```

Two presets ship: `default` (every binding it declares is listed below) and `vim`, which adds <kbd>h</kbd>/<kbd>j</kbd>/<kbd>k</kbd>/<kbd>l</kbd> alongside the arrow keys - but only where a letter isn't typed input, so text and filter fields keep the arrows.

## Actions

The actions are the fixed set of intents the fields understand - the bindings behind them are configurable, the intents are not. Every `Action` case:

| Action                                           | Meaning                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------- |
| `MoveUp` / `MoveDown` / `MoveLeft` / `MoveRight` | Move the cursor or caret                                             |
| `Accept`                                         | Commit the editor's value                                            |
| `Cancel`                                         | Close the editor without committing                                  |
| `Activate`                                       | Open the focused field, go into the focused panel, or press a button |
| `Back`                                           | Come back out of the panel you are in                                |
| `Quit`                                           | Close the dialog that is open, else end the session                  |
| `ScrollUp` / `ScrollDown`                        | Move a scrolling region without moving the cursor                    |
| `Help`                                           | Show the focused field's help on a page of its own                   |
| `DeleteBack`                                     | Delete the character before the caret                                |
| `InsertSpace`                                    | Type a space                                                         |
| `NewLine`                                        | Insert a newline (textarea)                                          |
| `ExternalEdit`                                   | Hand off to the external editor (textarea)                           |
| `Complete`                                       | Accept the ghost-text completion (text, suggest)                     |
| `Increment` / `Decrement`                        | Step a bounded number                                                |
| `Toggle`                                         | Check an option, or flip a two-state switch                          |
| `SelectAll` / `SelectNone`                       | Check or clear every visible option                                  |
| `Grab`                                           | Pick up or drop the held item (reorder)                              |
| `Yes` / `No`                                     | Set a confirm directly                                               |
| `Reveal`                                         | Cycle the password display, or show hidden file-picker entries       |

The named keys a binding can use - every `KeyName` case: `Up`, `Down`, `Left`, `Right`, `Enter`, `Escape`, `Interrupt` (<kbd>Ctrl-C</kbd>), `Suspend` (<kbd>Ctrl-Z</kbd>), `Space`, `Backspace`, `Delete`, `Tab`, `Home`, `End`, `PageUp`, `PageDown`, `MouseWheelUp`, `MouseWheelDown`. Anything printable is bound as the character itself (`'q'`, `'?'`).

## The default bindings

What `default` actually declares, scope by scope. Every field inherits the base layer and overrides only what differs:

| Scope                                | Keys                                                                         | Action                                           |
| ------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------ |
| base (every field)                   | <kbd>↑</kbd> / <kbd>↓</kbd> / <kbd>←</kbd> / <kbd>→</kbd>                    | `MoveUp` / `MoveDown` / `MoveLeft` / `MoveRight` |
| base                                 | <kbd>Enter</kbd>                                                             | `Accept`                                         |
| base                                 | <kbd>Esc</kbd>                                                               | `Cancel`                                         |
| base                                 | <kbd>Backspace</kbd>                                                         | `DeleteBack`                                     |
| base                                 | <kbd>Space</kbd>                                                             | `InsertSpace`                                    |
| navigation                           | <kbd>Enter</kbd>                                                             | `Activate`                                       |
| navigation                           | <kbd>Esc</kbd>                                                               | `Back`                                           |
| navigation                           | <kbd>q</kbd>                                                                 | `Quit`                                           |
| navigation                           | <kbd>?</kbd>                                                                 | `Help`                                           |
| navigation                           | mouse wheel                                                                  | `ScrollUp` / `ScrollDown`                        |
| every field that takes no typed text | <kbd>?</kbd>                                                                 | `Help`                                           |
| number                               | <kbd>↑</kbd> / <kbd>↓</kbd>                                                  | `Increment` / `Decrement`                        |
| rating                               | <kbd>→</kbd> / <kbd>↑</kbd> and <kbd>←</kbd> / <kbd>↓</kbd>                  | `Increment` and `Decrement`                      |
| text, suggest                        | <kbd>Tab</kbd>                                                               | `Complete`                                       |
| template                             | <kbd>Tab</kbd> / <kbd>↓</kbd> and <kbd>↑</kbd>                               | `MoveDown` and `MoveUp` (between slots)          |
| textarea                             | <kbd>Enter</kbd>                                                             | `NewLine`                                        |
| textarea                             | <kbd>Tab</kbd>                                                               | `Accept`                                         |
| textarea                             | <kbd>Ctrl-E</kbd>                                                            | `ExternalEdit`                                   |
| confirm                              | <kbd>y</kbd>/<kbd>Y</kbd> and <kbd>n</kbd>/<kbd>N</kbd>                      | `Yes` and `No`                                   |
| confirm, toggle                      | <kbd>←</kbd> / <kbd>→</kbd> / <kbd>Space</kbd> / <kbd>↑</kbd> / <kbd>↓</kbd> | `Toggle`                                         |
| password                             | <kbd>Tab</kbd>                                                               | `Reveal`                                         |
| pause                                | <kbd>Enter</kbd> / <kbd>Space</kbd>                                          | `Accept`                                         |
| select (multiple), search (multiple) | <kbd>Space</kbd>                                                             | `Toggle`                                         |
| select (multiple), search (multiple) | <kbd>→</kbd> / <kbd>←</kbd>                                                  | `SelectAll` / `SelectNone`                       |
| file picker (single and multiple)    | <kbd>Tab</kbd>                                                               | `Reveal`                                         |
| file picker (multiple)               | <kbd>Space</kbd>                                                             | `Toggle`                                         |
| reorder                              | <kbd>Space</kbd>                                                             | `Grab`                                           |

`vim` inherits all of it and adds letters where typing can't swallow them: the panel browser gains <kbd>h</kbd>/<kbd>j</kbd>/<kbd>k</kbd>/<kbd>l</kbd> for all four directions, the single-choice select <kbd>k</kbd>/<kbd>j</kbd> for up and down, and the calendar <kbd>k</kbd>/<kbd>j</kbd>/<kbd>h</kbd>/<kbd>l</kbd> for week and day movement - each alongside the arrow keys, never replacing them.

The `every field that takes no typed text` row is why a field's own help stays reachable while it is open. Where the field takes typed characters the key is one of them, so the scope is skipped rather than fought over - which is also what the validation below would insist on.

Not everything on the keyboard routes through the map: a few field keys are fixed. The calendar's month and edge jumps (<kbd>PageUp</kbd>/<kbd>PageDown</kbd>, <kbd>Home</kbd>/<kbd>End</kbd>) have no action behind them and always keep their keys. <kbd>Ctrl-C</kbd> is fixed the other way round - it is answered above the routing, so it aborts from anywhere, including from inside an open field. <kbd>Ctrl-Z</kbd> is answered above the routing too, and [hands the terminal back to the shell](/live-screens#step-away-and-come-back) from anywhere.

`ScrollUp` and `ScrollDown` are what the wheel is bound to, and they move what you are looking at rather than where you are: the viewport shifts by a row, the overflow marks follow it, and the cursor stays on the row it was on. A region that was not declared to scroll ignores them, because there is nothing to move through. The next key that could move the cursor puts the region back under it, so looking ahead never costs you your place.

## Per-field-type overrides

Bindings are layered by **scope**: a base layer shared by every field, a navigation layer for the panel browser, and one layer per field type that overrides the base only where it differs (<kbd>Enter</kbd> inserts a newline in a textarea, <kbd>Space</kbd> toggles a checkbox option). To retune individual bindings, pass overrides on top of a preset - each names a scope, an action and its keys. Later bindings win, so re-declaring a scope-and-action pair replaces the preset's keys for it:

```php
use DrevOps\PhpTui\Block\FieldType;
use DrevOps\PhpTui\Input\Action;
use DrevOps\PhpTui\Input\Binding;
use DrevOps\PhpTui\Input\KeyName;
use DrevOps\PhpTui\Input\Scope;

$tui = (new Tui($form))->keys('default', [
  // Quit with x as well as q.
  new Binding(Scope::navigation(), Action::Quit, 'x'),
  // In the single-choice list, Tab accepts too.
  new Binding(Scope::field(FieldType::Select), Action::Accept, KeyName::Tab, KeyName::Enter),
]);
```

A binding's keys take three forms: a `KeyName` case for a named key, a single-character string for a printable one, or a `Key` for anything else - `Key::char("\x05")` is how the default preset binds <kbd>Ctrl-E</kbd>. A scope takes three forms too: `Scope::base()` (shared by every field), `Scope::navigation()` (the panel browser), and `Scope::field(FieldType::X)` - with `Scope::field(FieldType::X, multiple: TRUE)` targeting the multiple-collecting variant of a choice or file-picker field, which carries its own binding set (that's where <kbd>Space</kbd>-to-toggle lives).

The panel and editor hints are drawn from the live bindings, so they always reflect the active keys - remap quit to <kbd>x</kbd> and the footer says so.

### Letters in a multiple select

A multiple select filters its options as you type. The answer is the options you check, so the multiple select is the one text-taking scope where you can bind a printable character. A bound letter runs its action and skips the filter. To check every option on <kbd>a</kbd> and clear them on <kbd>n</kbd>:

```php
$tui = (new Tui($form))->keys('default', [
  new Binding(Scope::field(FieldType::Select, multiple: TRUE), Action::SelectAll, 'a'),
  new Binding(Scope::field(FieldType::Select, multiple: TRUE), Action::SelectNone, 'n'),
]);
```

The multiple search, `Scope::field(FieldType::Search, multiple: TRUE)`, keeps every letter for its query, because the query can drive a backend source.

## Your own commands

A `Command` binds keys to a handler of your own. Declare it in the same list as your overrides, with the label the hint line shows, the handler and the keys. Its keys take the same 3 forms a `Binding` takes:

```php
use DrevOps\PhpTui\Answers\Answers;
use DrevOps\PhpTui\Input\Command;

$drafts = [];

$tui = (new Tui($form))->keys('default', [
  new Command('save', function (Answers $answers) use (&$drafts): void {
    $drafts[] = $answers->toSummary();
  }, 's'),
]);
```

The handler receives the answers as they stand when the key is pressed. Its return value is ignored.

A command runs from the panels: on any row and on the buttons that end the form. While a field is open, its keys go to the field, so an open text field types <kbd>s</kbd> as a letter. The hint line follows the same rule. It lists each command after the panel's own keys, in the order you declared them, and drops them while a field is open.

A command needs a free key. Its key can't be one the navigation scope already binds, either directly or through the base scope, such as <kbd>q</kbd>, <kbd>?</kbd>, <kbd>Space</kbd> or <kbd>j</kbd> under `vim`. It also can't be another command's key. Either conflict throws when the facade is configured. To give a command a built-in's key, rebind the built-in first: `new Binding(Scope::navigation(), Action::Quit, 'x')` frees <kbd>q</kbd>.

## Presets and validation

A preset is a class listing its bindings. Subclass `DefaultKeyMap` to ship your own, name it directly with `->keys('\App\MyKeyMap')`, or register a short alias with `KeyMapManager::register('mine', MyKeyMap::class)` and then `->keys('mine')`.

Bindings are validated the moment they're set, so a bad key map is caught at configuration time, not mid-session:

- a key bound to two different actions in the same scope is a conflict;
- a command key already bound in the navigation scope, to an action or to another command, is a conflict;
- a printable character bound in the base scope, or in a scope whose field consumes typed input (text, template, number, rating, password, textarea, search, suggest, toggle and file picker), would be un-typeable and is rejected - control characters like <kbd>Ctrl-E</kbd> are exempt, since they're command keys, never typed content;
- an unknown preset name, a character binding that isn't exactly 1 character, a command with no label or no keys, or a command bound to <kbd>Ctrl-C</kbd> or <kbd>Ctrl-Z</kbd>, is rejected.
